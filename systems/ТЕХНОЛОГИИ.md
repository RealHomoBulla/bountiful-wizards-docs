## Куда идём — каким это будет на 100 %

Create является стержнем технологии: его кинетические машины, рецептурные KubeJS-слои, Create Metallurgy и AE2 образуют один загруженный и проверенный Forge-маршрут. При 100 % каждый статический рецепт загружается без ошибки, ключевые машины крафтятся в выживании, а транспорт доказывает заявленный маршрут предметов в игре.

Ограничение делается KubeJS-удалениями и переавторскими JSON-рецептами: это единственный доказанный в checkout механизм изменения Create/Metallurgy/AE2. В частности, исходный recipe id `createmetallurgy:crafting/materials/tungsten_wire_spool` удалён, а в data-слое есть 16 рецептов `*_light_bulb.json`; действительную загрузку этой замены ещё нужно принять в Forge.

Скоуп промышленной угрозы не считается завершённым: статические KubeJS hooks Siege существуют, но Java jar `factory_siege` не находится в активных каталогах. Включать его в релизную технологическую систему можно только после отдельного решения и Forge load-smoke.

## В работе

Gateway AI bridge статически принят: `GW-AI-03` отвергает Forge `FakePlayer`, который Gateways возвращает для playerless gateway; bytecode-probe фальсифицирует прежнюю реализацию, а merged `gradlew.bat build` зелёный. `GW-04/GW-05` всё ещё требуют изолированной Forge/game-приёмки, потому что jar не установлен. Client и server остановлены.

## На чём это стоит

- Create, AE2, Create Pneumatic Express, Create Metallurgy, Vintage и Sculk Horde присутствуют на client и server с совпадающими SHA-256; точные hashes и стороны — в отчёте измерения §«Воспроизводимые исходные данные».
- `12_Applied_Energistics.js` статически удаляет recipes по output id `ae2:vibration_chamber`, `ae2:charger`, `ae2:crank`, `ae2:inscriber` и задаёт `ae2:inscriber` с ingredient `ae2:charger`; это проверка исходника, не загрузки.
- `industrial_crucible.json` статически применяет tag `forge:plates/steel` и fluid registry id `createmetallurgy:molten_steel`; это опровергает старое утверждение о необходимости удалённых obdurium/tungsten, но не заменяет Forge-приёмку.
- `90_Siege_Core.js` и `90_Siege_Blocks.js` содержат fail-closed/inert-by-default gate `!siege on`; Java jar Factory Siege при этом отсутствует на обеих активных сторонах.
- Классы скорости и RPM здесь намеренно не выводятся из JSON `processingTime`: для ставки нужен отдельный разбор tick-loop bytecode с названными stack и duration.
