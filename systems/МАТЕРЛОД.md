> **Готовность: 0 %**

> **Ждёт твоего слова:** 1 сверка решения · **Проверить в игре:** 0 пунктов

## Куда идём — каким это будет на 100 %

Целевой матерлод сейчас **не определён**. RNS нельзя описывать как цель: текущий
`ИГРОВОЙ_ЧЕКЛИСТ.md` называет его уходящей веткой и запрещает тестировать Mine Head,
буры, Deposit Scanner и Otherside motherlode. Пока владелец не утвердит замену либо не
подтвердит снятие, здесь нет честного маршрута игрока, главного мода, ограничителей,
вырезанного контента или готового 100%-скоупа.

скоупа, интегрированного контент-слоя, принятой генерации или игровой приёмки. Вес
равный только потому, что ни одна подсистема не дошла до состояния, из которого можно
обоснованно дать ей больший вес.

тот даёт варианты A/B/C для RNS, а чеклист называет снятие решением владельца. Не
создавать второй вопрос и не тестировать ветку до сверки канонической записи.

| решение | источник |
|---|---|
| Сверить финальное состояние RNS: снять, сохранить инертным после выравнивания версий, или вернуть как новый staging-скоуп. | `OPEN.md` §1.289 и `ИГРОВОЙ_ЧЕКЛИСТ.md` (примечание про уходящую ветку). |

Игровых проверок не осталось: текущий чеклист прямо запрещает проверять Mine Head, буры,
Deposit Scanner и Otherside motherlode.

## 🔴 Что сломано

Канонические записи расходятся: `OPEN.md` §1.289 ещё показывает A/B/C для RNS, тогда как
`ИГРОВОЙ_ЧЕКЛИСТ.md` сообщает о решении снять его. Пока это не сведено, следующий
исполнитель может ошибочно вернуть уходящую ветку в работу либо удалить неутверждённый
контент.

## В работе

Подтверждённой активной реализации матерлода нет. В этой проверке не найдено authored
RNS-стейджинга в master KubeJS или FTB Quests; существующие статические `bw_lode` данные
не считаются работой в процессе без принятой загрузки и скоупа.

## Что не начато вообще

- Заменяющий RNS целевой маршрут поздней добычи.
- Утверждённый главный мод, ограничения и причины вырезания для этого маршрута.
- Авторский datapack/рецепты/квестовый gate под новый маршрут.
- Принятая Forge-загрузка, генерация в новых чанках и игровая приёмка нового маршрута.

## На чём это стоит

- `ИГРОВОЙ_ЧЕКЛИСТ.md`: RNS остаётся физически на обеих сторонах, но его Mine Head, буры,
  scanner и Otherside motherlode не тестируются как уходящая ветка.
- `OPEN.md` §1.289: записаны конфликтующие с чеклистом варианты будущего RNS; их нельзя
  выдать за принятое состояние страницы.
- `agents/economy/2026_08_28_SYSTEMS_MATERLODE_READINESS_MEASURE.md`: клиентский и
  серверный RNS-артефакты различаются по версии; пакетные структуры и конфиг —
  статические факты, а не доказательство живой генерации.

## Чем проверить

```powershell
python bountiful_wizards_REMAKE/tools/paths.py --client
python bountiful_wizards_REMAKE/tools/paths.py --server
```

Команды должны назвать реальные стороны; затем можно сверить, что RNS-артефакт всё ещё
лежит на обеих сторонах. Наличие JAR не считать приёмкой запуска.

```powershell
$master = python bountiful_wizards_REMAKE/tools/paths.py --master
$hits = rg -n -i -m 100 'create_rns|bw_rns|mine[_ -]?head|deposit[_ -]?scanner' `
  "$master/kubejs" "$master/config/ftbquests" 2>$null
if ($LASTEXITCODE -eq 0) { $hits } else { 'NO_AUTHORED_RNS_OR_MINE_HEAD_OR_SCANNER_REFERENCES_IN_MASTER_KUBEJS_OR_FTBQUESTS' }
```

Нормально для текущего уходящего состояния: печатается строка `NO_AUTHORED…`. Если
появится reference, это новый authored-контент, требующий скоупа и проверки загрузки.

```powershell
$master = python bountiful_wizards_REMAKE/tools/paths.py --master
Get-ChildItem "$master/kubejs/data/bw_lode" -Recurse -File -Filter *.json |
  ForEach-Object { Get-Content -Raw -LiteralPath $_.FullName | ConvertFrom-Json | Out-Null }
```

Нормально: команда завершается без ошибки разбора. Это утверждает только валидный JSON;
она не заменяет Forge-загрузку или генерацию мира.
